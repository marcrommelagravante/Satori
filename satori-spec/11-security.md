# Satori — Security Requirements

## 1. Threat Model
Protect workspace documents and prevent unauthorized data access, prompt-injection-driven tool abuse, unsafe uploads, and secret leakage.

## 2. Authentication
All protected data routes require a valid authenticated session.

## 3. Authorization
Every document, conversation, search, citation, report, and tool request must enforce workspace membership.

## 4. Tenant Isolation
Always scope database queries by authorized workspace ID.
Never accept a client-provided workspace ID as proof of access.

## 5. Upload Security
Validate size, MIME type, extension, and basic integrity.
Use storage keys generated by the server.
Do not execute uploaded files.

## 6. Secret Management
API keys and credentials are server-only environment variables.
Never expose Gemini/API secrets to browser code.
Never commit .env files or secrets to GitHub.

## 7. Prompt Injection
Treat retrieved document text as untrusted data.
Document instructions must not override system/application instructions.
Tool execution must be governed by application authorization and validation.

## 8. AI Data Leakage
Only provide Gemini with context authorized for the current workspace/user.
Do not retrieve unrelated workspace documents merely to improve answer quality.

## 9. SQL Safety
Use Drizzle parameterization/query builders.
Do not construct raw SQL from untrusted user text for ordinary operations.
Natural-language retrieval must never become unrestricted arbitrary SQL.

## 10. Rate Limiting
Add limits to uploads, search, chat, and AI tool operations before public deployment.

## 11. Logging
Do not log full sensitive document contents by default.
Prefer identifiers, timings, status codes, and safe metadata.

## 12. Error Handling
Return generic safe error messages to clients.
Keep internal diagnostic details in controlled logs.

## 13. Data Deletion
Provide deterministic deletion behavior and remove associated chunks/embeddings.
Handle storage deletion failure explicitly.

## 14. Real-World Testing
Use only files the tester is authorized to use.
Do not upload passwords, API keys, credentials, identity documents, or unnecessary personal records.

## 15. Security Acceptance
No cross-workspace retrieval.
No client exposure of secrets.
No direct tool bypass of authorization.
No arbitrary code execution from uploaded documents.
